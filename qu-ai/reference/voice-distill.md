# 风格蒸馏：把「你的写法」变成可执行的约束

> 改编自 女娲造人术（alchaincyf/nuwa-skill，MIT，作者花叔）的「蒸馏用户自己」流程，
> 裁剪为「为改写服务」的用途：不产出人物 Skill，只产出一份 `voice-profile.md`。

## 为什么需要这一步

去 AI 味只解决「不像机器写的」。但如果十篇文章十种口气，读者仍然会觉得假——那不是 AI 味，是**没有作者**。

本流程的目标：从你自己写过的东西里，提炼出稳定的表达特征，写进 `voice-profile.md`。之后每次改写都按这份档案约束，风格才不会漂。

## 什么时候跑

- `voice-profile.md` 仍是空模板，且用户要求「按我的风格改」
- 用户说「学我的写法」「像我写的」「别每篇都一个调」
- 用户主动提供多篇自己的旧作

用户只说了「去 AI 味」而没提风格，且档案为空：**先按模式 A 直接改写**，在结尾用一句话提示可以建立风格档案，不要打断交付。

## 一、收素材

需要用户提供，**不做网络搜索**——你的写作风格不在网上。

优先顺序：

1. 你自己写的长文（公众号推文、博客、知乎回答）——最能暴露结构习惯
2. 小红书 / 微博 / 朋友圈——暴露口语节奏和情绪强度
3. 口播稿、直播转录——暴露真实说话方式
4. 给同事写的说明、邮件、需求文档——暴露你在「非表演」状态下的用词

数量：**3–8 篇，每篇不少于 300 字**。少于 3 篇就不要跑，直接告诉用户素材不够，先按通用规则改写。

单篇也行但不稳：一篇只能看出「这一次的写法」，看不出「一贯的写法」。

## 二、提取维度

逐篇标注，再归并。只记**反复出现**的，一次性的不算特征。

| 维度 | 看什么 | 产出形式 |
|---|---|---|
| 句长 | 平均句长、最长句、是否有短句成段 | 「平均 25–35 字，每 3–4 句插一个 8 字以内短句」 |
| 高频词 | 你反复用的实词、动词、程度副词 | 列 10–20 个 |
| 禁用词 | 你从不用的词（对照 patterns.md 的 AI 高频词） | 列 10–20 个 |
| 口癖与连接 | 「其实」「说白了」「问题是」「然后」这类 | 列 5–10 个，注明出现位置偏好 |
| 段落结构 | 一段几句、是否用小标题、是否爱列点 | 描述 + 一个骨架 |
| 标点习惯 | 破折号、括号补充、问号、省略号的使用密度 | 各给「常用 / 少用 / 不用」 |
| 人称与语气 | 我/我们/你，命令式还是商量式，敢不敢下判断 | 一句话概括 |
| 举例方式 | 举自己的事、举别人的事、还是打比方 | 一句话 + 一个例子 |
| 开头结尾 | 怎么起（直给结论/场景/问题）、怎么收（戛然而止/回扣/行动项） | 各一句 |
| 情绪强度 | 克制 / 中性 / 外放 | 一句话 |

## 三、写档案

产出到技能目录下的 `voice-profile.md`，格式：

```markdown
# 我的写作声音

> 素材：<篇数> 篇，共约 <字数> 字，采集于 <日期>
> 素材清单：<文件名或来源，逐条列>

## 一句话画像
<比如：短句为主、爱用具体数字、判断给得直接、不用形容词堆砌>

## 句长与节奏
- 平均句长：<n> 字
- 节奏特征：<描述>

## 高频词（可以用）
<词表>

## 禁用词（不要出现）
<词表>

## 口癖与连接词
<列表 + 使用位置>

## 结构与标点
- 段落：<描述>
- 小标题：<有/无，风格>
- 破折号/括号/问号：<密度>

## 人称与语气
<描述>

## 举例方式
<描述 + 一个真实例子>

## 开头与结尾
- 开头：<模式>
- 结尾：<模式>

## 情绪强度
<描述>

## 已知盲区
<哪些维度素材不足、判断不稳，写清楚>
```

## 四、怎么用它改写

改写时把档案当作**声音约束**，与 `reference/patterns.md` 的模式检查并行：

- 句长、口癖、标点按档案还原
- 档案里的禁用词即使不属于 AI 高频词，也一并避开
- 结构骨架照档案走，不要套用通用的「总—分—总」

**关键边界**：只借表达方式，**不搬素材里的事实、数据、经历和立场**。素材里的「我上个月亏了 20 万」不能出现在新稿子里，除非用户这次也这么说了。

## 五、反模式（违反即作废）

| # | 不要做 | 为什么 |
|---|---|---|
| 1 | 编造用户没表现出的特征 | 档案一旦掺假，之后每篇都被污染 |
| 2 | 把通用写作道理包装成「你的特色」 | 比如「你善于用具体例子」——如果 3 篇里只出现 1 次，那不是特征 |
| 3 | 素材不足仍强行生成完整档案 | 宁可只写 4 个维度并标注盲区，也不要凑满 |
| 4 | 把素材内容搬进新文本 | 借的是声音，不是内容 |
| 5 | 用单一篇素材定全部维度 | 一篇的偶然性太大，至少 3 篇 |

## 六、更新

素材增加或用户说「我不这么写了」时重跑。保留旧版为 `voice-profile.prev.md`，方便对比哪里变了、为什么变。
